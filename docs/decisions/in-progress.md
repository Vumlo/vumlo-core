# Decisions: in progress

Accepted and partly built. Each line says what exists and what is missing, judged from the code and
`ARCHITECTURE.md`. Built parts are not repeated in [done.md](done.md).

- ADR-0007 — Domain events through a transactional outbox. Built: `events::emit` in the same transaction and the worker (0045). Missing: scheduled jobs (item `publish_at`, expired sessions).
- ADR-0024 — Item kinds. Built: `text`, `assignment`, `file`. Missing: `link`.
- ADR-0026 — Lessons made of steps, with self-check questions. Built: the question model, used by `quiz` (0050). Missing: the `lesson` item with steps.
- ADR-0070 — Module `ai_agent` ("Buddy"): a chat agent for students, teachers and admins, built on `module-api`; id `ai_agent`, never called "assistant" (a course role). One OpenAI-compatible adapter over `OutboundClient`, no new crate, no streaming. Its tools call existing service functions as the user's `Actor`, so it sees and does nothing the user cannot. Read tools run at once; every write is a stored proposal that runs only on the user's confirm (one request, one transaction, once). Students get a coach, never an author. One rolling chat per user in `mod_ai_agent`, deleted after `retention_days`, readable by nobody else. Admin settings: `endpoint`, `model`, secret `api_key`, `roles`, `daily_cap`, `retention_days`, `notice`. Built: the module with the chat, the read tools (`my_work`, `my_grades`, `teaching_overview`, `course_gradebook`), the cap, retention, the panel, and the proposal flow with the grading, deadline and content tools (`set_grade`, `publish_grades`, `set_deadline`, `create_module`, `create_text_item`, `create_assignment`, `create_quiz`; always drafts; `content::set_due_at` for the deadline). `ModuleState` carries `Institution` (the grading scale and the editor settings, nothing secret) so a module writes content under the core's own rules. A student's Buddy prepares `save_draft` and `submit_work` for text assignments, and the text of a draft must be words the student wrote in this chat (`tools::submitting::quoted`): text the model composed is refused, so the Buddy relays and never authors. An admin's Buddy also has `find_people` and `org_overview` and prepares `create_term`, `create_group`, `add_group_members` (students only, up to 50, all or none) and `reset_password`; `auth` and `org` export the service functions the admin routes already call. A reset is the one change with a secret: the confirm route makes and hashes the temporary password before its transaction, and the password is only in that response (`Cache-Control: no-store`), never in a proposal, the chat or a model prompt; the confirm answers `200 {temporary_password}` (null for every other change); an admin's own account is refused. All four packs of the plan are built. The desktop app shows the launcher: its `api` command carries the calls, it keeps no cached copy of `/modules/ai_agent/*` (offline, the Buddy is not drawn), and `POST …/messages` gets a 600 s timeout so a slow model is not taken for a lost connection.
- ADR-0071 — Modules get one launcher slot in `Shell`: a module with `web: true` may export a `Launcher` that the shell renders on every signed-in page (the Buddy button). No other slots; plugin tabs (0066) are unchanged. Built: `Shell` renders the `launchers` that `scripts/brand.mjs` collects from `web/src/modules/<id>/Launcher.tsx`.
- ADR-0035 — Submission drafts, attempts and deadlines. Built: drafts, numbered attempts, lateness. Missing: `on_deadline = auto_submit` is stored and validated but does nothing until the worker has a deadline job.
